# 候補者DB_test: インラインDBビュー化 & 本文セクション整理

対象: Notionワークスペースの「候補者DB_test」データベース(テンプレートページ + 候補者ページ全100件)。

## 背景・目的

候補者ページの本文には、選考プロセス・活動ログ・資料・職歴などを自動生成テキストとして表示するセクションがあったが、同じ情報を持つリンク型データベースビューを追加したことで内容が重複していた。本文を読むより、関連情報にリンクされたインラインDBビューを見る方が情報が追いやすいため、次の2段階で整理した。

## 実施内容

### 1. インラインDBビューの追加(全100ページ + テンプレート)

各候補者ページに以下のリンク型データベースビューを追加:

- 🏢 選考プロセス
- 🕒 活動ログ
- 📎 資料
- 💼 職歴
- 🏢 選考中の企業(フィルタ: フェーズ ≠ 辞退/却下/お見送り)
- 💼 求人(フィルタ: 紹介済み候補者 OR 応募済み候補者に自分を含む)

### 2. 重複する本文セクションの折りたたみ(全100ページ + テンプレート)

上記ビューと内容が重複する3つの自動生成セクション(🏢選考中の企業、🕒タイムライン、📎資料)を、「ビューを参照」の一行案内 + `<details>` トグル(クリックで旧テキストを展開)に置き換えた。本文の大きなテキスト自体は変更・削除せず、見出し行のみを編集する方式で実施(自動生成テキストの再現ミスによる事故を避けるため)。

📣申し送りセクションは畳んでいない(トグルの開閉境界としてのみ見出し行を編集)。

## 実施方法

Notion MCPツール(`notion-fetch` / `notion-update-page` の `update_content` コマンド)による手動編集。本リポジトリのコードは一切使用していない(このタスクを実行するスクリプトは存在しない)。

## 既知の制約

このワークスペースには、候補者ページの自動生成セクション(📌状況サマリー、👤候補者プロフィール、🏢選考中の企業、🕒タイムライン、📎資料)を定期的に再生成するSlack連携の同期処理が別途稼働している。この同期処理は`<details>`トグルの存在を認識しないため、次回の同期実行時に今回追加した折りたたみ表示が上書きされる可能性がある。恒久的な対応には同期スクリプト側(本リポジトリ外)の修正が必要。

### 編集パターン(`notion-update-page` / `update_content`)

各ページで4つの見出し行を、直前に`notion-fetch`した実際のテキスト(タイムスタンプ含む)に置き換えて編集する。本文の大きなテキストには絶対に触れない。

1. `## 🏢 選考中の企業（自動更新: T1）` → 同文言の後ろに以下を追加:
   `\n<span color="gray">（下の 🏢 選考中の企業 ビューを参照）</span>\n<details>\n<summary>旧形式テキスト（クリックで展開）</summary>`
2. `## 🕒 タイムライン（自動更新: T2）` → 先頭に`</details>\n\n`を追加し、末尾に1と同様の`<span>`+`<details><summary>`を追加(前セクションを閉じつつ自セクションを開く)
3. `## 📣 申し送り（自動更新: T3）` → 先頭に`</details>\n\n`のみ追加(このセクション自体は畳まない)
4. `## 📎 資料（自動更新: T4）` → 末尾に1と同様の`<span>`+`<details><summary>`を追加(最終セクションのため閉じタグ不要、Notionが自動で閉じる)

見出しが既に`<details>`を含む場合はそのページ・セクションはスキップ(二重ラップ防止)。見出し自体が存在しない場合もそのセクションのみスキップ。

### 承認プロンプトを減らす設定

`.claude/settings.local.json`(git管理外)に以下のNotionツールを許可リスト登録済み: `notion-fetch`, `notion-update-page`, `notion-query-data-sources`, `notion-create-view`, `notion-update-view`。同じ作業ディレクトリのセッションであれば引き継がれる。
